\section{What This Project Is}

ReDeal is a static, multi-page second-hand marketplace prototype for the Philippine market. Each HTML page is a real entry point, and its module script starts the controller for that page. The application uses browser APIs directly: DOM methods, events, URL parameters, and \code{localStorage}.

\begin{infobox}
\textbf{Technology boundary.} The runtime uses HTML5, CSS3, vanilla JavaScript ES modules, mock product data, local persistence, and no backend. There is no React, Vue, Angular, database, server API, or build pipeline in the application runtime.
\end{infobox}

The current source contains 15 seed products, local JPG product photographs, product-detail actions, a listing form, authentication pages, a profile page, and placeholder Messages and Requests pages. Phase 4 authentication is implemented in source but still requires browser verification before it should be presented as completely closed.

\subsection{How a page starts}

An HTML page loads CSS in the head and a module at the end of the body. The module imports only the code required by that page. \code{onReady(init)} runs the controller after the document is available.

\begin{lstlisting}
// marketplace.html
<script type="module" src="js/pages/Marketplace.js"></script>

// Marketplace.js
import { onReady } from '../utils/events.js';
import { products, getProducts } from '../data/products.js';
onReady(init);
\end{lstlisting}

The browser therefore follows a predictable path: \textbf{HTML page} loads a \textbf{controller}; the controller imports \textbf{components, utilities, and data}; the data layer reads or writes \textbf{localStorage}; DOM updates show the result.

\section{Data Layer: Products and Created Listings}

\subsection{Seed products}

\code{js/data/products.js} exports the 15 seed records, category and condition values, and helper functions. Each product has an ID, title, Peso price, category, condition, seller information, one image path, location, description, defects, and creation timestamp.

The module imports created products from \code{storage.js} and merges them before exporting \code{products}:

\begin{lstlisting}
const createdProducts = getCreatedProducts();
export const products = [...createdProducts, ...seedProducts];

export function getProduct(id) {
  return products.find(p => String(p.id) === String(id)) || null;
}
\end{lstlisting}

The \code{String} coercion means URL values such as \code{?id=6} can match product IDs stored as strings or numbers. Missing and invalid IDs return \code{null}, which Product Detail converts into the Not Found state.

\subsection{Marketplace processing}

\code{getProducts(options)} calls \code{filterProducts} and then \code{sortProducts}. Search checks the title, category, description, and location. Category and condition are exact filters. Sorting supports newest, oldest, price-low, and price-high.

\subsection{Created listings}

\code{storage.js} owns the \code{redeal\_created\_products} key. \code{addCreatedProduct} prepends a new product so it appears first. \code{getNextId} checks both seed and created products to generate the next numeric ID.

\code{CreateListing.js} adds the authenticated seller's name, initials, and \code{sellerId}. After saving, it navigates to the new product detail URL. On the next page load, \code{products.js} reads the created record and includes it in the marketplace catalog.

\subsection{Login and signup}

\code{Login.js} and \code{Signup.js} perform client-side validation. The submit button begins disabled in HTML. Validation runs on input, blur, or terms changes, so empty forms do not display errors immediately.

On success, \code{loginUser}, \code{registerUser}, or \code{demoLogin} writes the user and session, migrates legacy favorites, dispatches \code{auth:login}, and redirects. The login page first checks \code{sessionStorage} for a destination saved by the route guard.

\subsection{Route guards}

Protected controllers call \code{requireAuth} before continuing. If no valid session is found, the guard stores the intended route and navigates to \code{login.html?redirect=...}. Valid sessions return the user object and allow page initialization to continue.

\subsection{Header and UserMenu}

\code{Header.js} renders the current auth state and listens for login/logout events. \code{UserMenu.js} creates the dropdown only when opened, traps keyboard focus inside it, closes on outside click or Escape, and calls \code{logout} for the Log Out action.

\section{Favorites and Shared Components}

\subsection{User-scoped favorites}

\code{favorites.js} derives a storage key from the current user when no explicit ID is supplied. Authenticated data therefore uses \code{redeal\_favorites\_<userId>}; the unscoped \code{redeal\_favorites} key remains available for legacy migration.

The main operations are:

\begin{tabular}{@{}p{3.6cm}p{3.3cm}p{6.4cm}@{}}
\toprule
\textbf{Function} & \textbf{Return} & \textbf{Purpose} \\
\midrule
\code{getFavorites} & \code{Set} & Reads favorite IDs for the current or supplied user. \\
\code{setFavorites} & none & Serializes a set into localStorage. \\
\code{isFavorite} & boolean & Checks whether one product ID is stored. \\
\code{toggleFavorite} & boolean & Adds/removes an ID and emits \code{favorites:changed}. \\
\code{initProductFavorites} & none & Copies stored favorite state into product records before rendering. \\
\code{migrateLegacyFavorites} & none & Copies the old shared key into the first user-scoped key. \\
\bottomrule
\end{tabular}

Product cards and Product Detail listen to the same-document custom event so two controls on the same page can update together. Browser tabs do not synchronize because no \code{storage} event listener is implemented.

\subsection{ProductCard}

\code{Card.js} creates DOM nodes with \code{createElement}, sets text content for product fields, and attaches image error handling. A card click navigates to \code{product.html?id=N}; the favorite button stops propagation, calls the favorites utility, updates its pressed state, and invokes the page callback.

\subsection{Modal}

\code{Modal.js} creates a dialog shell, backdrop, title, body, and action footer. It traps focus, closes on Escape and backdrop interaction when configured, and returns a Promise from \code{close}. The Product Detail message and offer handlers close first, then schedule the confirmation alert after close completion.

\subsection{DOM and event utilities}

\code{dom.js} contains thin query wrappers, safe element creation, HTML escaping, class helpers, and CSS-variable helpers. \code{events.js} contains delegation, DOM-ready handling, debounce/throttle, custom event helpers, focus trapping, outside-click handling, and keyboard activation helpers.

\begin{infobox}
\textbf{Security boundary.} User-controlled text is generally inserted with \code{textContent} or created text nodes. Where Product Detail uses a template string for display data, it applies \code{escapeHtml}. Authentication remains prototype-only because passwords and sessions are stored in localStorage.
\end{infobox}

\section{Product Detail and Demo Journeys}

\subsection{Product Detail journey}

The page reads \code{window.location.search}, trims the \code{id}, looks up the record, initializes its favorite state, renders the product, and binds delegated listeners. The share action tries the Web Share API, then clipboard access, then opens a modal containing the raw current URL in an input. Thumbnail and main-image error handlers reveal the placeholder state.

The strongest classroom path is:

\begin{enumerate}
  \setlength{\itemsep}{1pt}
  \item Open Marketplace and choose a product card.
  \item Observe the URL change to \code{product.html?id=N}.
  \item Toggle the desktop or mobile favorite button.
  \item Open Message Seller or Make Offer and show the prototype validation/confirmation flow.
  \item Return to Marketplace and verify the card state in the same browser session.
\end{enumerate}

\subsection{Create Listing journey}

The Create Listing controller first calls \code{requireAuth}. It validates title, price, category, condition, description, location, and image URL. It then builds a product record with the current user's seller identity, calls \code{addCreatedProduct}, and redirects to the new product detail page. On a subsequent page load, the storage record is merged with seed products by \code{products.js}.

\subsection{Profile journey}

Profile requires authentication at module initialization. It renders the current user's initials, name, email, guest badge when appropriate, own listings filtered by \code{sellerId}, favorites filtered by stored IDs, and settings. Name updates are persisted by \code{updateUser}; logout clears the session and redirects to the homepage.
